## 0. 背景与已拍板决策

本轮用户反馈三个启动期观感问题（灰屏 / 双进程不同步 / 闪烁，诊断见会话记录），并拍板：

1. **小窗口启动**（PlayerSettings 改 Windowed + 小默认分辨率），缓解 Unity 个人版 splash
   期间的全屏灰闪（SplashHider 藏窗有 20ms 轮询竞态窗口期，全屏 1920×1080 漏一帧就很扎眼）。
2. **不默认弹设置窗口**——开机自启场景必须直接进桌宠形态，不能弹窗。设置窗口只从托盘打开。
3. **重做设置窗口**，挂托盘入口。历史注：09-18 回退（5188061）时曾随双进程实验一起
   连根删除旧 IMGUI 设置面板；本次为用户主动要求恢复，旧实现（git 9fd7857 引入、
   341 行）的成熟机制（PointerHover 矩形上报、Commit 数据流）可直接参考演进。
4. **托盘菜单收纳**：从"一堆单功能按钮"（8 项扁平）改为游戏化管理方式（分组 + 子菜单）。

## 1. 托盘菜单信息架构

### 现状（扁平 8 项）

```
召唤：贴图史莱姆 / 召唤：果冻软体 / 召唤：碎裂软体 / 召唤：液态玻璃
收回：最近一只物种 / 收回：一只液态玻璃
────────
退出
```

### 新结构（两级子菜单，右键）

```
透明桌宠
├─ 召唤 >
│   ├─ 液态玻璃
│   ├─ 贴图史莱姆
│   ├─ 果冻软体
│   └─ 碎裂软体
├─ 收回 >
│   ├─ 最近一只物种
│   └─ 一只液态玻璃          ← 只剩一只时灰显
├─ ────────────
├─ 抓屏隐形（折射真实桌面）✓   ← 复选
├─ 开机自启动 ✓               ← 复选
├─ 缩放 >                      ← 单选组（圆点）
│   ├─ 50% / 75% / 100% / 150% / 200%
├─ ────────────
├─ 设置…
├─ ────────────
└─ 退出
```

- **左键单击托盘图标 = 打开设置窗口**（高频入口游戏化：单开菜单最低层级）。
- 菜单**结构静态、状态动态**：勾选/单选/灰显由 `PetWindowSetup.RefreshTrayMenu`
  在每次弹出前刷新（读一次配置 + 一次注册表）。三个快捷开关的理由：改这几项
  不该逼用户开面板（TrafficMonitor 的菜单也是这个分工——高频项进菜单、低频项进面板）。
- 菜单动作路由不变（`GlassRole.OnSummon/OnRecall` 分岔：glass 本地、物种转发命令文件）；
  缩放走与面板同一条链（本进程事件 + 落盘 + `config` 命令通知物种进程）。

### 出处：TrafficMonitor 的托盘菜单怎么做的（2026-09-22 读其源码所得）

`TrafficMonitorDlg.cpp` 的 `OnInitMenu(CMenu*)`（MFC 的 `WM_INITMENUPOPUP`）——
菜单资源是静态的，所有动态感都在弹出前注入：`CheckMenuItem`（勾选）、
`CheckMenuRadioItem`（单选组，如窗口不透明度 100/80/60/40）、`EnableMenuItem`（灰显）、
`ModifyMenu`（连文案都能改，如插件名）；动态**项目**则启动时 `AppendMenu` 追加
（"选择网络连接"子菜单）；`SetDefaultItem(ID_OPTIONS)` 让"选项…"加粗。
我们复刻了勾选/单选/灰显三项，`SetDefaultItem` **有意不做**——左键单击直达设置
已经是更快的路径，默认项只在键盘操作菜单时有意义。
一处改进：它的 `OnInitMenu` 跑在消息泵的嵌套栈上（MFC 没有别的选择），
我们的刷新回调挪到 `Pump` 的**顶层栈**、构建 HMENU 之前执行（回调要读配置/注册表，
按本项目"同步 IO 不进窗口过程嵌套栈"的纪律）。

### NativeTray 需要的扩展（Platform 层）

| 能力 | 实现 |
| --- | --- |
| 子菜单 | `TrayMenuItem.Children`（递归 `AppendMenuW` + `MF_POPUP`；菜单 id 仍按叶节点扁平编号，动作队列机制不变） |
| 勾选态 | `Checked` → `MF_CHECKED`（快捷开关） |
| 单选组 | `Radio` + `Checked` → 叠 `MFT_RADIOCHECK`（画圆点）；同一时刻只点亮一项 |
| 灰显 | `Enabled=false` → `MF_GRAYED`（**灰显而不是隐藏**：位置稳定、用户看得出"这项现在不适用"） |
| 弹出前刷新 | 构造参数 `onRefreshMenu`（次 `Pump` 顶层、构建 HMENU 前调用）——TrafficMonitor 的 `OnInitMenu` 等价物 |
| 左键响应 | 窗口过程补 `WM_LBUTTONUP` → 打开设置（与右键 `TrackPopupMenu` 互斥：先判断按键） |

标志位组装抽成纯函数 `NativeTray.FlagsFor`（NUnit 按 **Win32 字面值**钉住——
写错不报错、只表现异常，本项目在 DXGI/IID 上吃过同类亏）；"当前缩放该点亮哪一档"
抽成 `TrayMenuState.NearestPresetIndex`（滑条给的是 1.0499999 这种值，不能 == 比）。

## 2. 设置窗口形态

### 结论：玻璃进程内 IMGUI 自绘"拟物经典对话框"

**不做真 Win32 窗口**：Platform 层需自建窗口类 + 消息循环 + 与 Unity 渲染/透明窗口共存，
复杂度不成比例；历史上"原生设置窗口"尝试也在 09-18 回退中废弃（用户拍板）。
IMGUI 方案与 HUD 同构，复用现成机制：

- **穿透兼容**：面板矩形每帧 `PointerHover.ReportHover` → 面板区域可交互、面板外仍穿透
  （旧 SettingsPanel 已验证该路径，09-13 卡死收口时它就是上报方之一）；
- **数据流**：Start 时 Load 工作副本 → 控件只改工作副本 → Commit 统一
  "发布 EventTopic（本进程即时生效）→ Save 落盘 → 广播 ConfigSaved"。

### 视觉：经典白色对话框风（用户参照"Windows 安装器"）

- 底色 `#F0F0F0`（经典 dialog 灰白），1px `#6B6B6B` 边框，四角直角；
- 顶部标题栏 28px：扁平深灰底 + 白字「透明桌宠 · 设置」+ 右侧 [×]；
- 控件：IMGUI 原生 Toggle / HorizontalSlider / Button 重皮肤（黑字、经典观感）；
- 字体：`Microsoft YaHei UI` 动态字体（HUD 同款加载方式，透明窗口中文必需）；
- 尺寸 480×500（2026-09-22 随左列页导航由 380 加宽），默认屏幕右上角（工作区内），**标题栏可拖动**。

### 布局线框（左列图标页导航 + 右侧内容区，四组）

> 2026-09-22 改：顶部横排页签 → **左列图标+文字页导航**（对齐 TrafficMonitor 的
> 选项对话框：宿主对话框 + 自绘页签控件 `CTabCtrlEx`（带图标、`SetItemSize`/DPI 缩放）
> + 每页一个子对话框（`m_tabN_dlg.Create(IDD_..., &m_tab)`））。页数会随功能增长，
> 竖排不压缩每个页签的宽度。面板相应从 380 加宽到 480。
> 它还有"页内容高于页签区时页内滚动"（子对话框模板高度喂给 `SetScrollbarInfo`），
> 我们用 `GUILayout.BeginScrollView` 达到同一效果——**当前四页都装得下，
> 所以看不到滚动条**；它的价值在设置项继续增长之后。

```
┌──────────────────────────────────────────────┐
│ 透明桌宠 · 设置                           [×] │  ← 标题栏（拖动区）
├──────────┬───────────────────────────────────┤
│ ● 桌宠    │  桌宠管理                          │
│ ▲ 物理    │  液态玻璃    ●●          [−][+]   │
│ ▢ 窗口    │  贴图史莱姆  —           [−][+]   │
│ ◆ 关于    │  果冻软体    —           [−][+]   │
│          │  碎裂软体    —           [−][+]   │
│（选中行   │  整体缩放   ────●────     1.00   │
│  深底白字）│  贴图角色   [ 史莱姆·绿  ▾ ]      │
│          │                                   │
│          │  （物理页）抛射开关 ☑ / 重力 ──●── │
│          │   初速上限 ──●── / 甩出倍率 ──●──  │
│          │  （窗口页）始终置顶 ☑ / 抓屏隐形 ☐ │
│          │  （关于页）版本 / 一句话 / 仓库地址 │
└──────────┴───────────────────────────────────┘
```

页图标是**程序化生成的 16×16 白色实心图形**（圆/三角/方框/菱形），绘制时用
`GUI.color` 上色（选中=白、未选中=深灰）——不用字体符号，避免换台机器缺字形变方块。

### 与 TrafficMonitor 的重要差异：不做 确定/应用/取消

它是"编辑副本 → `DoModal()` → IDOK 后 `ApplySettings()` 拷回并逐项算 diff"；
我们改一下就即时生效（拖滑条能实时看到缩放），落盘 0.4s 防抖。
桌宠是常驻小面板，"改完再点确定"没有收益；代价是**取消了"反悔"能力**，
将来若出现不可逆设置项再补 Apply 态。

- 「桌宠管理」的 [−][+] 直接复用 `PetSummonRequested` / `PetRecallRequested` 事件
  （GlassRole 已有分岔路由），不是新协议；
- 物种数量**只读** `summoned_pets.json`（物种进程每秒已在写，玻璃进程读显示，零新增同步）。

### 交互细节

- **ESC 语义冲突**：ESC 当前是全局硬退出（`PetWindowSetup.Update`）。面板打开时 ESC 只关面板：
  窗口层检查 `SettingsPanel.Visible`，可见则发关闭事件并 return，不退程序；
- 打开/关闭走 EventBus 新主题 `SettingsPanelToggleRequested`（载荷 bool，托盘/热键/ESC 共用）；
- 面板开在玻璃窗口（置顶层）内，天然盖在物种窗口上，无 z 序问题。

## 3. 数据流与跨进程分发

### 写方仲裁（关键约束）

`config.json` 在 Player 下**只由玻璃进程写**：

- 物种侧控制器写 `petScreenX/Y` 的遗留路径已被 `SetPersistPosition(false)` 关闭
  （SpeciesPets.Spawn 统一设置，位置持久化归 `summoned_pets.json`）——本设计将该约定
  固化进代码注释与本文档；编辑器单场景 Play 模式保留原行为；
- 每次 Save 前先 Load 最新（Load-modify-Save，旧实现已如此），防止覆盖并发变更。

### 设置变更分发链

```
控件改动 → 工作副本
        → EventBus 发布对应主题            （玻璃进程即时生效：置顶/玻璃相关）
        → PetConfigStore.Save              （落盘）
        → ConfigSaved 广播
        → RoleEnvironment.SendSpeciesCommand("config")   （通知物种进程）
```

物种进程 `DrainSpeciesCommands` 收到 `config` → 重新 Load → 本地重发布
`PetScaleChanged` / `ThrowParamsChanged` / `CharacterChanged` 应用到运行中的宠物。
（窗口置顶/自启/抓屏隐形是玻璃侧语义，不转发。）

## 4. 启动行为

- **任何启动方式（手动/开机自启）都不弹设置窗口**，直接进桌宠形态（小窗口 splash 方案
  另行处理灰闪，见待办）；
- 首启引导 HUD（introShown，已有）文案补一句"右键托盘图标打开设置"；
- 自启开关 = `NativeStartup.SetStartup`（注册表，已实现）+ `config.autoStart` 落盘同步。

## 6. 观感验收手段（这一块没有"定点图"）

- **`EditorTools.UiSnapshot`**：IMGUI 走不了 `Camera.Render()`（那条路只渲染相机
  看到的物体），故该工具进 Play 模式、等玩家循环真跑起来后截屏 →
  `%TEMP%/pet-ui/settings.png`；改前改后各一张供人工对比（与 `LiquidGlassSnapshot`
  同一套纪律）。踩坑已记在文件头：`EnterPlaymode` 的**域重载**会清掉静态字段与
  `EditorApplication.update` 订阅，须用 `SessionState` + `[InitializeOnLoadMethod]` 重挂。
- **它是编辑器 Game 视图的截图，不是桌面实机**：布局/配色/字体/控件位置与实机同源
  （同一份 IMGUI、同一套窗口内像素坐标），但**看不到**透明合成叠在桌面上的效果、
  穿透与悬停手感、以及托盘那个原生弹出菜单（后者根本截不到屏）。实机验收照旧在
  exe 上做（点托盘图标开面板）。
- **`TransparentPet/打开设置面板（Play 中）`**（`PlayHelper`）：运行时面板只由托盘
  唤起（建托盘那段被 `#if !UNITY_EDITOR` 跳过），编辑器里本来没有入口——改面板观感
  时连看都看不到。这个菜单项发的是与托盘同一条事件。

## 6. 风险与开放问题

- IMGUI 自绘下拉的展开行高估算（旧实现有 ExpandedItemGuess 经验，可沿用）；
- 面板拖动与宠物拖拽输入天然不冲突（面板 ReportHover 时指针不在宠物命中区），
  但需回归验证 PetInputArbiter 仲裁；
- 若后续设置项膨胀（如逐物种参数），再考虑 uGUI/Canvas 重构——当前规模 IMGUI 足够。
