## P1 托盘重加图标无重试（P1 修复项的残留缺口）

- **状态**：✅ 代码与单测完成；**2026-09-23 追修根因后自愈才真正生效**（此前虽标 ✅，实机语义一直是失效的，见下）。实机杀 explorer 验证并入下方实机验收清单。
- **文件**：`Assets/Scripts/Platform/NativeTray.cs`（宿主窗口创建 / `ReaddIcon` / `Pump`）、`Assets/Tests/Editor/Platform/TrayReaddRetryTests.cs`
- **现状（2026-09-20 首修）**：`TaskbarCreated` 到达后只 `NIM_ADD` 一次；失败仅 `Debug.LogWarning`。
- **缺口**：重加可能撞上 explorer 任务栏初始化未完成（MS 文档提示的竞态），单次失败 = 图标再次永久消失，且无第二次机会（下次 TaskbarCreated 要等 explorer 再死一次）。托盘是设置/退出唯一入口，自愈必须可靠。
- **方案**：`ReaddRetryState`（可注入时钟的纯逻辑）：首次失败装填 5 次预算，`ReaddIcon` 失败时递减并登记待重试，`Pump()` 每帧检查、按 0.5s 间隔补试至成功（`Clear` 复位预算）或预算用尽（不再空转）。
- **2026-09-23 追修的根因（这才是自愈一直没生效的原因）**：宿主窗口最初用 `HWND_MESSAGE` 创建为 **message-only 窗口**，而 Win32 规定 message-only 窗口不接收广播消息（MSDN《Window Features》：`HWND_MESSAGE` 窗口被排除在 `HWND_BROADCAST` 目标之外）——explorer 重启的 `TaskbarCreated` 正是靠广播送达，于是这条消息**从未到达**窗口过程，2026-09-20 那版 `ReaddRetryState` 根本等不到触发时机，自愈整条路径是死代码。现把宿主改为**隐藏的普通顶层窗口**（`WS_POPUP` + `WS_EX_TOOLWINDOW|WS_EX_NOACTIVATE`，1×1、从不 `ShowWindow`），广播得以送达，重试自愈真正生效。
- **同时收口的实现细节**：重加从 wndproc 的嵌套栈改为把请求入队、在 `Pump()` 顶层执行（守"同步跨进程 IO 不进窗口过程嵌套栈"的纪律，与早前托盘菜单动作同款处理）；托盘创建失败改为 `Debug.LogWarning` + 发布新事件 `EventTopics.PlatformErrorRaised`（载荷 string，见下方事件清单）。
- **验收**：`TrayReaddRetryTests` 5 项锁定装填/间隔消耗/用尽/成功复位四段语义（时钟注入）；实机杀 explorer.exe 验证图标恢复并入实机验收清单。

## 新增 Core 事件（2026-09-23，随本轮修复落地）

- **`PlatformErrorRaised`（载荷 string）**：Platform 层关键设施失败的统一出口——`Debug.LogWarning` + `EventBus.Publish`（当前发布方是 `NativeTray` 的宿主窗口创建失败）。语义是"降级 + 告警"而非"崩溃"：发布方不抛异常、不中断主流程；当前无强制消费者，作为 HUD / 诊断面板的扩展点（无订阅者时发布本身无副作用）。定义见 `Core/EventTopics.cs`。
- **`AutoStartChanged`（载荷 bool）**：开机自启开关的**结果通知**——注册表已写、配置已落盘之后发布（发起方是写盘入口：`PetWindowSetup` 托盘菜单项与 `SettingsPanel` 窗口页各一处），订阅方按新状态刷新勾选态/开关显示。修复了此前托盘与设置面板两侧各写各的、互相覆盖的缺陷；`SettingsPanel` 的同步由 `SettingsPanelAutoStartSyncTests` 钉住。
